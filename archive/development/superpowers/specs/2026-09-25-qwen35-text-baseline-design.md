## 4. 模型配置与两类状态

以下为官方配置在 2026-09-25 的观察值；实施时应固定模型 revision 并保存配置指纹，不能把浮动 `main` 当作永久实验标识。

| 项目 | Qwen3.5-4B 文本部分 |
| --- | --- |
| 配置入口 | 顶层 `model_type=qwen3_5`，文本字段位于 `text_config` |
| 层数 | 32；24 个 `linear_attention`，8 个 `full_attention` |
| 层序列 | 每组 3 层线性注意力后接 1 层完整注意力，共 8 组 |
| hidden_size / vocab_size | 2560 / 248320 |
| 完整注意力 Q 头 / KV 头 / head_dim | 16 / 4 / 256 |
| 线性注意力 key 头 / value 头 | 16 / 32 |
| 线性 key/value head_dim / conv kernel | 128 / 128 / 4 |
| 配置权重 dtype / recurrent state dtype | BF16 / FP32；运行时仍须核查实际张量 |
| 其他需要保留的语义 | Attention output gate、partial rotary、位置构造与 MRoPE 配置 |

不要用 `hidden_size / num_attention_heads` 覆盖显式 `head_dim`，不要把 Q 特征宽度和包含 gate 的投影总输出宽度混为一谈。小模型文本 FFN 按实际配置/实现读取，不因家族介绍而假定其为 MoE。

两类状态分别观察：

1. Full Attention 的历史 K/V，大小随缓存 token 数增长。层索引必须保留模型的原始层编号；未来紧凑 KV 层编号不能与原始层编号混用。
2. Gated DeltaNet 的 recurrent state 和 convolution state。其状态张量通常具有固定形状，但内容随着处理过的 token 更新，不等同于历史 token 的 K/V 数组。固定状态大小也不代表 Prefill 计算量与长度无关。

在 BF16、B=1、T=4096 的假设下，普通 K/V 理论有效大小为：

`2 × 8 × 1 × 4096 × 4 × 256 × 2 = 134217728 bytes = 128 MiB`。

128 MiB 仅包含 8 层完整注意力的 K/V，不含递归/卷积状态、权重、激活、工作空间和分配器保留显存，不是整个推理请求的显存占用。第一课若尚未创建状态张量，必须将其实际占用标为“未测”，不能记为 0。

## 5. 第一阶段的组件与职责

### 5.1 配置与 tokenizer 检查

继续使用 `week3/inspect_model.py`，保持现有检查能力，同时增加明确的模型类型分派：Qwen3 读取顶层；Qwen3.5 读取 `text_config`。未知类型、缺失字段、非法维度、层类型数量与层数不一致应给出可定位的错误，不能悄悄当作全注意力模型。

提供只读配置模式，允许未下载权重时完成 CPU 学习。分词模式只访问显式指定的本地模型文件，不隐式联网或自动安装依赖；不要求 CUDA。默认学习目标改为 Qwen3.5-4B，文件缺失时明确提示准备步骤，不自动退回旧模型。

输出至少包括模型标识、文本层类型及数量、相关维度、假设 dtype、完整注意力 KV 公式与结果。递归/卷积状态单列，不能合并为一个伪精确的“总缓存字节”。

对同一提示词应用一次 chat template，比较模板直接分词与渲染后 `add_special_tokens=False` 编码的 IDs。记录实际模板、thinking 设置、EOS 和特殊 token；不复制旧模型的 18 token、1024 hidden_size 或 EOS 值。模板配置不支持某个选项时明确报错或说明实际行为，不声称已经关闭 thinking。

新配置的形状练习应使用实际 token 数 L：`input_ids=[1,L]`，`hidden_states=[1,L,2560]`；单 token Decode 分别为 `[1,1]` 和 `[1,1,2560]`。

### 5.3 自己的最小生成循环

计划在 `week3/minimal_generate.py` 中实现单卡、batch=1、无 padding 的短文本生成。默认短提示词，最多生成 16 个 token，输出上限可显式调整；首次不测试长上下文上限。

本项目负责：输入准备、Prefill/Decode 控制、缓存传递、贪心选 token、EOS/长度停止、逐步日志、请求结束后的状态引用清理。Transformers 负责模型 forward、算子和参考缓存实现。主循环不得调用现成 `generate()`；参考库生成只能作为另行标注的辅助检查。

循环语义：Prefill 的最后位置 logits 选择第一个输出 token；下一次 forward 才把这个 token 作为输入推进状态。结束时最后选出的 token 未必已进入模型缓存。

记录 `processed_tokens` 与 `generated_tokens`，避免一个含糊的 `length` 同时表示全部状态。此阶段不做 KV 压缩，尚不需要自创逻辑/物理双长度压缩机制。position/mask 按当前模型接口构造和验证，不将所有层都当作可查询普通 K/V 长度的对象。

不允许两个独立请求共享可变缓存对象。成功、EOS、长度停止或异常都应释放本次循环持有的缓存引用；不能声称引用释放必然导致 `nvidia-smi` 立刻降到零。

### 5.4 状态观察与数值对拍

计划在 `week3/verify_generation.py` 中进行同模型验证，记录每类缓存的层编号、shape、dtype、逻辑处理位置和实际张量字节。依照当前 Transformers 缓存类读取，不能假定旧式 tuple 接口。

对比路径 A：每一步对固定 token 前缀完整重算且不复用上一轮状态；路径 B：先 Prefill，再逐 token 使用自己的缓存。两条路径使用相同模型权重、输入 IDs、dtype、位置语义，均为 eval 模式。

采用 teacher forcing：每一步送入事先固定的同一个 token，不让两边独立采样后输入分叉。至少覆盖一次 Prefill 和连续多个 Decode，以及新请求重新开始。每个位置报告 finite 检查、形状、最大/平均绝对误差、相对 L2 误差、top-1 与前两名 margin。参考向量范数为零时单独报告，不发生除零。

容差必须在验收运行前写入测试配置，依据 dtype 与参考路径的重复/精度诊断选择并记录理由；尚无校准依据时仅产出诊断报告，不打印“正确性通过”。不能看见待验收结果后不断放宽阈值。top-1 不同须解释 margin 和数值误差，不能仅凭生成文字相似宣告对齐。

还需验证 A 请求结束后 B 的结果与 B 单独运行一致，以检测状态串用。异常后的下一次请求也应从新状态开始。

- 学习时间不足：优先完成单请求正确性和清晰文档，明确延后原生适配/优化，不杜撰成果。
