# GDN 第 1 课：重复计算核查与融合后端评估

日期：2026-10-11。性质：源码与依赖核查；本课尚未修改计算代码、安装依赖或运行融合性能测试。

## 当前执行链

layer_compute.py 的 gated_delta_net：
输入 → QKV 投影 → 拼接 conv 历史 → depthwise conv + SiLU → Q/K/V →
计算 beta/g → chunk 或 recurrent 核心 → gated RMSNorm → out_proj → 返回 conv/recurrent。

核心只处理递推，不包含完整 GDN 的卷积、投影和输出门控。换核心不意味着整个 GDN 融合成一个 kernel。

## 已确认的重复工作

1. raw_q,raw_k=q,k 保存原始张量引用后，q=q*...、k=k*... 是非原地计算，产生新结果。
2. 这些新 Q/K 被归一化、repeat_interleave、转 FP32。
3. hf_torch_chunk 分支却使用 raw_q/raw_k，并传入 use_qk_l2norm_in_kernel=True。
4. 所以上面的外部 Q/K 准备在 chunk 分支没有消费者。不是对同一输出连续归一化两次，而是先算一套不用的，再让核心算实际使用的。
5. fresh 路径提前创建的 recurrent 零矩阵、cached 路径 state.recurrent.float()，以及公共 recurrent.float()，在 chunk 分支也没有作为 initial_state 传入；传入的是 None 或原 state.recurrent，返回后覆盖 recurrent。只有需要实际转换时才产生额外转换开销，不能把每次 .float() 都算成新 kernel。
6. recurrent 分支确实使用外部归一化后的 Q/K 和 FP32 recurrent，不能全局删除上述操作。

建议最小改法：提前确定 use_chunk；把外部 Q/K 归一化、扩头、FP32 recurrent 准备放入 recurrent 分支；chunk 分支保持原始输入和原核心调用，beta/g/输出逻辑不变。此处只是建议，尚未实施。

另一个候选是 state.conv.clone()：当前后续 cat 不修改源张量，存在减少副本的空间；应单独验证状态不被意外原地更新，不与上述改变合并。next_conv.clone() 涉及输出独立存储，不因“看见 clone”就删除。

不能误删：beta/g（两分支均消费）、conv 状态承接、输出 gated norm、最终 state dtype 转换和资源池 copy_。

## 融合路线及接口边界

候选为 FLA 的 chunk_gated_delta_rule（Prefill/多 token 延续）与 fused_recurrent_gated_delta_rule（优先评估单 token 延续）。当前源接口含 initial_state/output_final_state；以最新接口接入前必须锁定实际版本，不能假设所有旧版本相同。

第一版应保持：
- 单请求执行，先不同时引入 packed 多请求。
- Q/K/V 的布局与扩头方式不变。
- 已计算的 g/beta 直接传入，暂不开 gate/beta 内部融合，防止重复激活。
- 归一化只执行一次，epsilon/计算精度需核对。
- recurrent 按 [B,HV,K,V] 的 K-first 布局，不能因 K=V=128 看不出 shape 差异就忽略语义。
- 获取返回 state 并显式写回本层、当前请求 state_slot；不能假定外部核心会自动修改我们的资源池。
- 尤其检查返回 FP32 recurrent 与现有 BF16 池之间的舍入政策。不能顺便改变状态精度来掩盖差异。

当前上游接口及源码：
- [chunk 核心](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/chunk.py)
- [recurrent 核心](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/fused_recurrent.py)

“chunk”在这里还有算法内部 tile 的意思；它与调度器每轮处理多少 prompt token 不是同一个配置。

## 验证顺序

1. 重复计算清理：要求同分块新旧输出、conv/recurrent 逐元素一致，覆盖 fresh T=1、fresh T>1、cached T=1、cached T>1，以及非 chunk fallback。
2. 单层融合：固定相同核心输入，对拍输出和 final_state；预先定义误差与生成验收标准，不能看到结果后随意放宽容差。
3. 真实层/引擎：分段边界、所有权、批次换序、slot 回收复用、长序列数值累计。
4. 原有整段/分块差异继续单独跟踪，不把“与同分块参考一致”当成质量已合格。
5. 预热排除 JIT 编译，独立 profiling 检查 kernel/搬运；关闭 profiler 做交错 A/B，不能引用别的 GPU 的加速比。

本课验收：chunk 分支最终传 raw_q/raw_k 时，外部计算得到的 q/k 为什么可以跳过？recurrent 分支为什么不能一起跳过？
